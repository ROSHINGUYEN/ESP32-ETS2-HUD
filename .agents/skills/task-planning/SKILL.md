# Task Planning

1. Restate the desired behavior in one sentence.
2. Define observable acceptance criteria.
3. Identify in-scope and out-of-scope files/behaviors.
4. Inspect the existing implementation before proposing new architecture.
5. Break work into small verifiable steps.
6. Prefer the smallest plan that meets the request.
7. Mark unknowns and blockers instead of inventing requirements.
8. Start implementation after enough information is available; do not over-plan trivial fixes.
9. After each step, verify it before moving on.
